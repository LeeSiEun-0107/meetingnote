## 화면

화면은 4종이다: 목록 · 넣기 · 상세 · 할 일.

배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다. 요소 `id` 는 그 파일에 적힌 그대로 쓰며, 화면을 다시 만들 때도 바꾸지 않는다. 배치는 이 문서에 옮겨 적지 않는다.

| 화면 | 역할 |
| --- | --- |
| 목록 | 첫 화면. 저장한 회의록을 카드로 표시하고 검색으로 조회 |
| 넣기 | 녹취 파일 업로드 후 받아쓰기, 요약 · 결정사항 · 할 일로 구분 |
| 상세 | 목록에서 카드를 누르면 뜨는 가운데 겹침 창 |
| 할 일 | 여러 회의의 담당자와 기한만 모은 표 |

| 요소 | id |
| --- | --- |
| 검색 입력 | `q` · `from` · `to` |
| 목록 칸 | `cards` |
| 넣기 폼 | `title` · `metAt` · `attendees` |
| 파일 · 본문 | `file` · `body` |
| 버튼 | `btnUp` · `btnSave` |
| 결과 세 칸 | `result` |
| 상세 창 | `modal` |
| 제목 수정칸 | `mTitle` |
| 할일표 본문 행 | `todoBody` |

## 디자인

- UI 는 맥OS 스타일로 한다.
- CSS 라이브러리는 Tailwind 를 쓰며, 깔끔하고 모던하게 만든다.

## 왜 이렇게 나누는가

관심사 분리(Separation of Concerns) 원칙에 따른다. 한 문서는 한 가지 질문에만 답한다.

- 무엇을, 왜 만드는가 → 01 (제품)
- 어떻게 동작해야 하는가 → 02 (명세)
- 어떻게 짓는가 → 03 (설계)
- 무엇부터 하는가 → 04 (작업)
- 어떤 규칙으로 쓰는가 → 05 (규약)

이렇게 나누면 바뀌는 이유가 다른 내용이 서로 섞이지 않는다. 예를 들어 화면 디자인이 바뀌어도 제품 정의나 API 명세는 건드리지 않는다. 지시가 문서와 어긋나는지도 해당 문서의 조항만 보면 판단할 수 있어 유지보수가 쉽다.
