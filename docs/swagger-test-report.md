## 3. 확인된 동작

- **AUTOINCREMENT:** 앞선 화면 테스트에서 id 1 을 지운 뒤 이번 테스트의 첫 저장이 id 2 로 만들어졌다. 지운 id 를 다시 쓰지 않는다.
- **시간대:** 입력 `2026-10-08T05:30:00+09:00` 이 `2026-10-07T20:30:00Z` 로 저장되어 UTC 변환이 동작한다.
- **세 갈래 구분:** 잡담("점심 메뉴", "회식 장소")은 결과에서 빠졌고, 논의만 된 항목은 결정사항에 들어가지 않았다. 할 일은 `내용 | 담당자 | 기한` 형식이며 기한은 말한 그대로("이번 달 말까지") 저장됐다.

## 4. 관찰 사항 (결함은 아님, 판단 필요)

1. **오류 응답 형식이 둘이다.** 검증 실패(400/422)는 `detail` 이 `[{field, message}]` 배열이고, 404/415/413/`from` 형식 오류(400)는 `detail` 이 문자열이다. 프론트는 문자열만 읽도록 되어 있어, 검증 실패 시 `요청에 실패했습니다 (400)` 같은 일반 문구가 나온다. 화면에서 필드별 안내가 필요하면 형식을 맞춰야 한다.
2. **날짜 검색은 UTC 기준이다.** `from`/`to` 가 UTC 날짜로 비교되므로 한국 시간 오전 9시 이전 회의는 전날로 검색된다. `02-specs.md` 에 시간대 규정이 없어 그대로 두었다.
3. **브라우저 콘솔 오류 19건**은 의도한 4xx 응답(400/404/413/415/422)에 대한 리소스 로드 로그다. 서버 오류(5xx)는 없었다.

## 5. 이번에 검증하지 않은 것

- **502 (Gemini 호출 실패):** Swagger 에서는 키를 끊을 수 없어 하지 않았다. 앞선 스크립트 검증에서 `502` 와 "구분 실패 시 201 + 빈 값"을 확인했다.
- **PUT 의 빈 `body`, 200자 초과 `title`** 같은 경계값.
- 동시 요청, 대용량(25MB 근처) 정상 업로드.

## 6. 테스트 방법 메모

- Swagger UI 의 파라미터 입력칸은 입력 후 약 350ms 뒤에 값이 반영(debounce)된다. 첫 시도에서는 이를 기다리지 않아 응답이 한 칸씩 밀려 읽혔고, 대기 시간을 늘린 뒤 전 케이스를 다시 실행했다. 이 보고서는 재실행 결과다.
- 업로드용 임시 파일(mp4, 30MB wav, 샘플 wav)은 테스트 후 삭제했다. 테스트로 만든 회의록도 모두 삭제해 DB 는 비어 있다.
